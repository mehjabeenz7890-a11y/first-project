# MindCare AI

**An Intelligent Mental Wellness Screening, Risk Assessment and Personalized Recommendation Platform**

> Understand Your Mind. Track Your Progress. Improve Your Well-being.

This is a full-stack academic project: a React frontend, a FastAPI backend,
and a modular ML/NLP pipeline that screens self-reported wellness data and
returns an explainable, non-diagnostic risk assessment with personalized
recommendations.

⚠️ **This is an educational project.** It does not diagnose medical or
mental health conditions, does not replace a licensed professional, and its
training data is entirely synthetic.

## 1. Generate the dataset and train the models

```bash
cd training
pip install -r ../backend/requirements.txt
pip install imodels shap  # optional, for the interpretable FIGS model + SHAP
python create_dataset.py --rows 10000 --out ../datasets/mindcare_dataset.csv
python train_models.py
python evaluate_models.py   # prints an accuracy/precision/recall/F1 table
```

This populates `saved_models/` with:
- `rf_<target>.joblib` — RandomForest classifiers (used for live inference)
- `figs_<target>.joblib` — interpretable FIGS models (imodels), used for explainability
- `label_encoder_<target>.joblib`, `input_encoders.joblib`, `feature_columns.joblib`
- `metrics.json` — full evaluation report

Targets trained: `primary_concern`, `risk_level`.

`recommendation_category` and `therapy_suggestion` are **not** trained as
separate models. They're derived with rules directly from the predicted
`primary_concern` (+ risk level and a couple of raw questionnaire fields like
sleep quality, exercise hours, and panic episodes) in
`backend/app/services/recommendation_service.py` — the same rule-based
approach already used for the lifestyle tips. Both fields are close to a
deterministic function of `primary_concern` by construction, so a second
layer of classifiers on top of the first model's output would add
complexity and an extra failure point without adding accuracy, and a rule
table is far easier to explain and defend in a viva than another black-box
model.

## 2. Run the backend

```bash
cd backend
cp .env.example .env        # edit SECRET_KEY before any real deployment
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

API docs (Swagger UI) will be at `http://localhost:8000/docs`.

The first registered user is a normal user. To make a user an admin (for
`/api/admin/*` endpoints), set `is_admin = 1` on their row in `mindcare.db`
directly, or add a small script — this is intentionally manual for the
academic scope of this project.

## 3. Run the frontend

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

Visit `http://localhost:5173`. Register an account — a default profile is
created automatically — then take an assessment.

## 4. Or run everything with Docker

```bash
docker compose up --build
```

Backend on `:8000`, frontend on `:4173`.

## Architecture

```
User → Register/Login → Profile → Assessment (questionnaire + free text)
                                        │
                        ┌───────────────┴───────────────┐
                        │           Stage 1: NLP          │
                        │  emotion, sentiment, keywords,  │
                        │  crisis-language detection      │
                        └───────────────┬───────────────┘
                                        │
                        ┌───────────────┴───────────────┐
                        │        Stage 2: ML models        │
                        │  RandomForest (+ FIGS/imodels)   │
                        │  → primary concern, risk level   │
                        └───────────────┬───────────────┘
                                        │
                        ┌───────────────┴───────────────┐
                        │  Stage 3: Recommendation engine   │
                        │  rule-based, transparent advice,  │
                        │  incl. recommendation category &  │
                        │  therapy suggestion (derived from │
                        │  primary concern + raw features)  │
                        └───────────────┬───────────────┘
                                        │
                        Stored in DB → Dashboard, History,
                                        Floating chatbot
```

The pipeline is intentionally modular (NLP → ML → rules) rather than one
monolithic model, so each stage is independently testable and explainable —
important both for engineering quality and for defending the design in a
viva.

## Tech stack

| Layer      | Tech |
|------------|------|
| Frontend   | React 18, Vite, Tailwind CSS, React Router, Chart.js, Axios |
| Backend    | FastAPI, SQLAlchemy, SQLite (dev) |
| Auth       | JWT (python-jose) + bcrypt |
| ML         | scikit-learn (RandomForest), imodels (FIGS), joblib |
| NLP        | Lexicon-based emotion/sentiment detector (swap-in point for sentence-transformers/DistilBERT) |

## Safety notes

- The chatbot never diagnoses or prescribes medication, and immediately
  surfaces a crisis message (not emergency dispatch) if crisis-related
  language is detected in either the assessment free-text or the chat.
- Every result page carries an explicit non-diagnostic disclaimer.
- The dataset is synthetic; do not present model outputs as clinically
  validated.

## Extending this project

- Swap `app/services/nlp_service.py` for a real `sentence-transformers`/
  `DistilBERT` pipeline (the interface — a single `analyze(text)` function —
  is already set up for a drop-in replacement).
- Add SHAP-based per-prediction explanations in `ml_service.py` (currently
  uses global RandomForest feature importances as a stand-in).
- Add PDF/CSV export on the Result and History pages.
- Add PostgreSQL for production via `DATABASE_URL`.
